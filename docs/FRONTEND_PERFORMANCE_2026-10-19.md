# 前端公共刷新路径分析与优化

本次针对“所有界面都卡顿”检查公共运行时与全局浮层。下列结果来自离线宿主测试和
P4 交叉编译，不能替代整机 CPU、帧率或触摸延迟的实测。

## 旧前端与实际入口

| 路径 | 当前用途与处理 |
| --- | --- |
| `quickapp/homeassistant/app.js`、desktop 下的同名 JS | 同步的米家前端源文件；由生成器更新资源与授权摘要，不能只修改其中一个副本 |
| 三份 `homeassistant_resource.c` | 不同集成入口的生成产物；桌面 Makefile 链接 desktop 下的一份，不会同时运行三套米家页面 |
| 历史 `glass_hass_ui.inc`、旧播放器/PV 页面 | 已从当前源码移除；历史补丁和报告不是正在运行的界面 |
| `ouo/`、`ouo_resource.c` | 旧 JS 球体源码仍可用于历史实验；当前桌面 Makefile 未链接该资源，Grok Ball 入口转到原生大球 |
| `app/jizura/upstream/` | 第三方源码与离线实验输入，不是当前桌面周期执行的前端 |
| `qpk_runtime.c` | 录音机、米家、相机和电脑 CLI 等快应用共享的 QuickJS/LVGL 桥接层，本次修复重复文字写入 |
| `glass_wake_mini.inc` | 每轮桌面循环都会经过的全局服务，本次修复静止浮层反复设置样式与收起后重复查旧结果 |

仅删除未编译的历史文件不会降低当前 CPU 占用。本次保留来源与生成关系，修改实际执行路径。

## 已修复的开销

1. `ui.setText` 原来无条件调用 LVGL。项目使用的 LVGL 实现在
   `lv_label_set_text` 中先使对象失效，再释放/分配文字缓冲区并刷新文字布局。
   现在标签、按钮文字和数值文字与当前内容相同时跳过该步骤；不增加逐控件字符串缓存。
   参数转换仍然执行，并在转换后核对控件代次，防止 `toString` 删除并复用控件后写错对象。
   省略号状态下 LVGL 可能临时修改文字缓冲区，此时保守地继续写入，避免误跳过真实更新。
2. 小球静止期间不再每轮设置相同位置、透明度和前景层级，也不重复写入相同识别文本。
   动画值发生变化时仍更新；出现新顶层对象时仍恢复浮层顺序。没有加入唤醒轮询节流。
3. 小球已收起且结果/播报均结束时，不再每轮扫描对话历史并复制上一轮结果。
   收起时仍有待完成的播报会继续处理，进入大球页和新请求接管保留原有语义。
4. 原生语音服务页只写入变化的文字；没有自有录音或 AI 结果时直接返回，跳过无用的状态复制。

没有新增生产代码中的可变全局状态，也没有修改音频采样、模型、设备控制或网络重试策略。

## 定向验证

| 用例 | 结果 |
| --- | --- |
| 真实 QuickJS + LVGL：标签、按钮、数值各设置相同内容 1000 次 | 修改前 3000 次 LVGL 文字写入；修改后 0 次 |
| 三个控件各设置一次不同文字 | 3 次写入，内容正确 |
| 字符串转换删除并复用原控件 | 拒绝过期句柄，保留新控件内容 |
| 静止小球运行 1000 次服务循环 | 位置、透明度、前景设置各 0 次 |
| 小球收起且任务结束后运行 1000 次循环 | 旧结果查询 0 次 |
| 小球转入大球后仍有待播报内容 | 完成一次播报；新唤醒立即处理，后来的录音请求取得所有权 |
| P4 RV32 交叉编译 | 公共运行时、桌面和相关助手源文件通过；未重新链接/烧录整机固件 |

宿主用例启用 ASan/UBSan，没有访问真实麦克风、网络服务或家中设备。
新增入口为 `render_frontend_performance.c` 与 `wake_mini_performance_host.c`，分别通过
`tools/render_all_ui.py --harness-source ...` 和 `tools/test_wake_mini.py --harness-source ...`
运行。文字用例需要先完成 LVGL 布局，避免把创建期间的临时省略号当作稳定状态。

历史 `wake_mini_host.c` 综合场景在后台重启断言处仍失败：其模拟前台录音完成后没有等待
已有的 1500 ms 重试间隔。本次未将它报告为通过，也未为通过旧夹具改变生产重试逻辑；
新增定向入口复用服务替身，单独验证此次性能变化与必要的所有权边界。

整体实机卡顿是否完全消除尚未验证；上表的写入次数不能换算成整机加速倍数。
