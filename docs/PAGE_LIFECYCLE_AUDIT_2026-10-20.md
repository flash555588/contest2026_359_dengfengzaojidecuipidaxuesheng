# 全页面生命周期与遮挡开销检查（2026-10-20）

本次从桌面启动入口、页面创建/删除回调、定时器、异步回调和动画逐项检查，
并使用实际 LVGL 控件树与 QuickJS 绑定验证。基线是性能分支的 `e18115bc`。
此前公共文字写入优化见 [前端性能分析](FRONTEND_PERFORMANCE_2026-10-19.md)。

## 发现与修复

主要入口没有测出退出后不断累积的旧控件或页面定时器。实际发现的是：
锁屏和全屏歌词页面保留下层页面，而 `lv_obj_is_visible()` 不检查其上方的
不透明兄弟对象。因此下层页面仍可能整理文字、更新图表、读取小球 SD 帧。

新增 `glass_ui_visibility.h`，只在确定有完整、不透明、无变换的顶层页面覆盖
整个显示器时延后绘制。部分弹窗、半透明遮罩、圆角和移动/缩放中的覆盖层
保守处理；覆盖层自身与位于其上方的小球继续显示。新建页面无需等到下一次
定时刷新才显示初始文字；显式隐藏和非活动屏幕仍被识别。

| 页面/组件 | 本次处理 |
| --- | --- |
| 首页、天气详情、聊天/创作/助手工作区 | 被完整遮挡时跳过界面刷新；恢复后读取最新状态 |
| 大球会话 | 暂缓波形和结果卡片绘制，保留语音、AI、播报状态机 |
| 原生 Grok 小球 | 遮挡后暂停已有定时器，不再发起下一帧读取；揭开后的绘制事件恢复，不新增隐藏轮询器 |
| 桌宠 | 继续推进引擎状态，遮挡期间跳过绘制 |
| Wi-Fi、蓝牙鼠标、配置二维码页 | 遮挡期间跳过展示刷新，后台任务与令牌时效继续处理 |
| 音乐、全屏歌词、PV | 跳过被遮挡视图的绘制，保留播放服务 |
| 系统性能 | 遮挡时继续采样并保存历史，延后文字与图表更新 |
| 米家快应用 | 使用 `ui.isVisible()` 延后构建和绘制，继续连接、请求完成、控制确认；恢复后更新最新状态 |
| 电脑 CLI | 延后绘制，继续处理请求及任务状态；恢复后补绘 |

录音机、文件操作和相机的完成处理没有被整体暂停。它们的轮询同时承担
保存录音、取消操作、交接预览等职责，不能仅因页面被遮挡就停止。

## 覆盖范围

生命周期入口为 `app/espdl-quickapp/tests/render_all_page_lifetime.c`。
每个状态执行打开、顶层锁屏覆盖、解锁恢复、退出，核对所有权、退出后的
屏幕/顶层控件数、全部 LVGL 定时器数（包括暂停的）及运行中的动画数。
先预热共享字体和控件缓存，再检查各轮是否恢复到相同基线。

| 分类 | 检查的入口与临时状态 |
| --- | --- |
| 系统 | 关于、控制面板、全部应用、Wi-Fi、蓝牙、鼠标、系统性能、天气、环境趋势、配置页 |
| 文件 | 浏览器、详情、新建对话框、图片预览、复制状态、删除确认 |
| 音乐 | 音乐空间、全屏歌词、PV、搜索输入框 |
| AI | 聊天、创作、助手、大球、输入框、模式选择、完整回复、新对话确认、放弃确认、AI 配置 |
| 语音与录音 | 原生语音服务、录音机列表、删除确认、录音状态（服务替身） |
| 家居与电脑 | 米家总览、米家设置、电脑 CLI；米家其余设备详情/控件另有前端用例覆盖 |
| 媒体与应用 | 相机、相册、网络直播、ESP-DL、桌宠、桌宠输入框、2048、Hello、消息提示与对话框 |
| 公共层 | 首页、四种锁屏布局、顶层遮挡顺序及揭开后的原页面恢复 |

媒体检查使用真实相册布局；网络直播/本地视频的展示构造器保留，解码线程和
网络流由宿主替身代替。快应用执行实际 JS 与 LVGL 绑定，定时调度由确定性
夹具驱动。不能将这些结果视为真实音视频线程、麦克风或网络服务的压力测试。

## 验证与限制

- 47 个页面/临时状态，普通动效和减少动效分别检查两套主题，每个状态重复三轮，共 564 次切换。
- 独立遮挡用例验证透明度、尺寸、圆角、变换、层级顺序，以及初次打开即可绘制。
- 实际小球在模拟的 2000 ms 遮挡窗口内新增读盘、换帧、定时回调均为 0；揭开后读取及显示恢复。
- 系统性能页在遮挡期间追加有效采样，揭开后展示最新值。
- 实际 QuickJS 可见性绑定、电脑 CLI 遮挡后补绘通过；米家 149 项前端用例通过，其中包括隐藏期间完成同步及延后构建。
- 电脑 CLI 请求状态回归通过；P4 RV32 对象编译通过，包括桌面、运行时、原生小球、桌宠和生成的米家资源。
- 桌面对象 `.data/.bss` 仍为 733/112640 字节，运行时仍为 320/1617 字节；这些是对象统计，不是重新链接的最终固件余量。

宿主启用 ASan/UBSan。进程退出时全局 LVGL/字体缓存仍由进程持有，
`detect_leaks=0`，因此这里只报告控件、定时器、动画的生命周期检查和运行时
内存访问检查，不宣称通过完整堆泄漏扫描。没有重新烧录设备，也没有测得
整机帧率或触摸延迟提升倍数。先前旧全局唤醒综合夹具的失败边界见前一份报告。

复现时先准备原项目的宿主 LVGL 缓存和 app 依赖，再运行：

```sh
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
PAGE_AUDIT_MOTION=1 python3 tools/render_all_ui.py \
  --apps /path/to/prepared/apps --cache /path/to/lvgl-host-cache \
  --output /tmp/page-audit --grok-assets /short/path/to/sd-banks \
  --harness-source app/espdl-quickapp/tests/render_all_page_lifetime.c
```

不设置 `PAGE_AUDIT_MOTION` 则验证减少动效模式。输出 `lifetime.jsonl` 记录
逐状态计数，`render-sources.json` 记录源码摘要；素材不随本次代码变更上传。
