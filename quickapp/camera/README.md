# 相机快应用

## 当前版本：2026-10-16

以下说明以当前 ESP32-P4 v3.2 固件为准，后文为早期测试记录。

采用横屏相机布局：完整 1024×600 内容区，去除系统日期栏、返回大按钮和应用标题栏；右侧使用白色圆形快门、黄色照片模式和圆形退出入口。设备列表、参数与刷新收进控制面板，退出相机恢复普通页面的状态栏与安全区域。待机提示与真实预览明确区分。通用布局检查覆盖 640×400、800×450、1024×504 和 1024×600；设备列表使用固定数量按钮分页。预览不增加页面上浮或连续装饰动画。

实际取景也使用右侧工具区。CSI 保留原有直接采集显示路径，工具区覆盖右侧边缘，照片在绘制控件前保存完整原始帧；USB MJPEG 按比例适配左侧图像区，解码时保留右侧控件内存，仅在状态变化时重绘工具区。没有增加全帧的旋转或复制。

右侧图像/控件边界按 128 字节缓存行对齐。CSI 画完控件后通过显示驱动的真实 C2M 接口分成 16KiB 段同步，再切换显示页；这块配置的通用缓存刷新为空操作，不能替代该接口。同步失败会停止发布该帧并进入现有清理流程。全屏同时处理桌面父容器的 32px 偏移，退出后恢复原位置和高度。

界面每 500ms 检查会话状态，空闲时每 2 秒检查设备变化，准备与预览期间暂停设备枚举。保留设备代次验证、退出清理和现有拍照保存流程；不会主动挂载或格式化存储。无效帧间隔不会传给原生启动接口。

修改 `app/espdl-quickapp/overlay/apps/system/desktop/camera/app.js` 后执行 `python tools/generate_camera_ui.py`，同步本目录脚本与固件内嵌资源。

### 带声音录像

点击右侧“照片”切换到“视频”，进入取景后点击红色快门开始录制，再次点击停止保存；录制中退出也会请求停止并保存。保存完成前不能再次开始录像。录像需要已挂载且可写的 SD 卡与可用麦克风，文件位于 `/sdcard/videos/VID_*.avi`，不覆盖已有文件。目录异常、空间不足、采集或写入失败时返回错误；不静默降级为无声视频，不修改挂载或格式化配置。

当前配置为 RGB565 320×180、10 fps，PCM16 单声道 16 kHz 麦克风音频，使用带索引的 AVI。当前没有视频压缩，约 1.18 MB/s，每个文件最高 256 MiB，索引与剩余空间也可能提前触发停止保存。画面保留比例并加黑边，音频样本数决定输出帧数，画面处理跟不上时重复最近帧，避免音频时长累积漂移。照片模式保持原拍照流程。录像线程持有三帧队列与上一帧，不持有显示页；采集线程只做限频缩放拷贝，写文件和麦克风会话清理在录像线程完成。

麦克风沿用现有录音功能的设备独占、音乐停止等待、DMA 缓冲回收与退出清理。仅内置相机入口获得录像桥接方法；离开内置入口会撤销录制权限并请求停止。该接口不提供任意输出路径或音频设备参数。

`python app/espdl-quickapp/tests/run_camera_video.py` 在 Linux 下运行生产录像线程与 AVI 写入器，覆盖缺 SD、麦克风失败、并发启动拦截、三次停止/重新录制和权限撤销；使用 ASan/UBSan 与 FFmpeg 检查完整解码、双流参数及音画时长差。实际音频设备由宿主模拟，实板测试记录保存在工作区构建输出中。

验证命令：`node app/espdl-quickapp/tests/test_camera_app.js quickapp/camera/app.js`、`node --test app/espdl-quickapp/tests/camera_upgrade.test.cjs`。`render_camera_upgrade.c` 使用真实 LVGL/QuickJS 与 ASan/UBSan，检查全屏 600px 内容、标题栏隐藏、分页、实际指针启动/停止/退出及恢复普通页面布局；宿主硬件接口为模拟。`run_camera_controls.py` 检查生产 RGB565 控件颜色、环形快门、位置和缓冲区边界；`test_mjpeg.c` 增加行跨度与右侧工具区内存保留测试。宿主测试不代表实板画质、帧率或拍照持久化验收。

该快应用通过桌面运行时的 `system.camera` 原生桥接打开 `/dev/video0`，请求 1024x600 RGB565 帧，以二倍抽样生成 512x300 LVGL Canvas 取景。LVGL 保持运行，不再由相机直接接管 framebuffer。

支持取景、重试、拍照、本次最近照片回看和停止。桌面原有返回按钮负责退出应用。退出时等待采集线程结束，再停止流并释放缓冲区；若底层存储写入阻塞，退出仍可能等待写入结束，此处不承诺硬超时。

照片保存为 `/data/photos/IMG_0000.bmp` 等不覆盖已有文件的 RGB565 BMP，每张 307266 字节。必须已有可写的 `/data` 挂载；应用不会格式化或挂载存储。写入、刷新或关闭失败不会报告成功，并删除本次不完整文件。当前回看显示本次成功保存照片的内存副本，不支持跨启动相册或文件回读。拍照写入期间采集线程暂停取帧，UI 继续运行；不承诺拍照时预览连续或 30 fps。

源码在 `../native/qpk_runtime.c` 和 `../native/camera_photo.h`，界面为本目录 `app.js`。从工作区根执行 `wsl -d Ubuntu-22.04 -- bash camera-app/build-product.sh`，使用今日保留的 Make 构建树增量编译；可传入兼容构建树路径。脚本核对待覆盖运行时，拒绝覆盖未知改动。不是独立干净环境构建，未修改比赛仓或原有发布包。

输出位于 `../product-build/`，包含 ELF、BIN、配置、构建日志和 SHA256SUMS。该配置是 ESP32-P4 v1 测试配置，不适用于未经确认的 v3.2 硬件。尚未烧录。
