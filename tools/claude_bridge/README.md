# ESPClaw 电脑 CLI

设备入口：ESPClaw 左侧的 **电脑 CLI**。任务在电脑上执行，ESP 负责选项目、选 CLI、发任务、看进度、继续会话和停止。返回对话不会停止电脑任务。

Windows 上，Claude Code 默认使用原生交互终端：直接把真实控制台的输入、输出、错误句柄传给 `claude.exe`，不使用 `--print` 或 JSON 输出模式。电脑显示完整 Claude 界面、颜色、菜单和输入框，可以直接用键盘操作。ESP 的回复页同步最近的可见终端文字，并提供“上 / 下 / 回车 / 返回”原生按键；“发送输入”继续向同一个原生终端发送消息，“停止”结束终端及其子进程。首条任务作为 Claude 的位置参数传入，不会再通过标准输入重复发送。首次启动的目录信任、主题等原生界面仍会显示，需在电脑端处理。

原生 Claude 会话会持续打开，直到从 ESP 停止、在 Claude 中退出或关闭窗口（默认任务期限仍为 30 分钟）。返回 ESPClaw 对话不会关闭电脑终端。Claude 自己可能把窗口标题改成 `claude`，这是正常行为。Codex 和自定义 CLI 继续使用带可见窗口的事件/文字转发。仅切换 CLI 选择项不会启动空任务。使用 `python bridge.py --no-terminal` 可恢复 Claude 的后台结构化任务模式。

在电脑上运行 `Start-Bridge.ps1`，管理页为 <http://127.0.0.1:8787>。ESP 首次连接时填电脑局域网 IPv4 地址（例如 `http://192.168.31.95:8787`）和脚本输出的六位配对码。配对码每次服务启动重新生成，十分钟内有效且只能成功使用一次；已配对设备重启后无需重新配对。电脑服务需要保持运行；CLI 使用电脑当前登录状态。

点击控制页左上角 CLI 名称切换程序；项目旁边的 `+` 可以添加电脑上任意现有本机项目目录（不接受 UNC/设备路径）。点击“新任务”提交需求，完成后“继续追问”接续该 CLI 的会话。“停止”只结束该任务及其子进程。

## CLI 支持

| 类型 | 已实现能力 | 权限处理 |
| --- | --- | --- |
| Claude Code | 自动发现、完整原生终端、屏幕文字同步、持续输入、会话续接、停止 | 单次操作可在 ESP 上允许或拒绝，240 秒未处理则拒绝 |
| Codex | 自动发现、JSON 事件、任务、续接、停止 | workspace-write；超出沙箱的操作不自动放行，错误显示在过程页 |
| 自定义 CLI | 注册启动参数、文字输出、任务、停止；可选持续输入 | 使用注册程序本身的权限和交互规则 |

自定义程序：将 `clis.example.json` 按实际路径修改后放到 `.state/clis.json`，重启桥接。`command` 是参数数组，首项是原生可执行文件。脚本必须显式指定解释器，例如 `["python.exe", "-u", "D:/tools/worker.py"]`。不要填写整条 shell 命令。任务通过标准输入传递；`input: true` 保持输入通道打开，ESP 的“发送输入”可继续发送一行。一次性 CLI 不设置 `input`，收到任务后关闭标准输入。

自定义 CLI 使用通用标准输入输出接口。Claude Code 已适配原生终端；其他依赖真实终端、全屏 TUI、鼠标或交互式登录的程序仍需专用适配，不能保证任意 CLI 原样直接接入。Gemini、OpenCode 等可在安装后按各自非交互参数注册，尚未实测。

## 边界与恢复

监听只作用于桥接启动的会话。Claude 的 `UserPromptSubmit / PreToolUse / PostToolUse / Stop / StopFailure` 等本地 HTTP hooks 自动同步回合状态，区分“终端仍开着”和“本轮完成／失败”；有后台任务时不会把回复结束当作所有工作结束。监听回调不批准权限、不重放命令，单次权限确认仍走独立接口。回调仅接受本机、任务专用密钥和匹配的会话编号；外部 API 请求体上限仍为 16 KiB，本地事件回调上限为 1 MiB，结果摘要仍为 4 KiB。

屏幕同步每 3 秒发送一次健康心跳；超过 10 秒未收到时显示“终端同步暂时中断”，电脑任务继续运行。读取屏幕失败不会结束 CLI。回合最终结果会保留，退出提示不会覆盖它；API 错误后即使终端正常退出，也不会记成执行成功。依赖 Claude Code 支持并启用这些 hook；缺少事件时只显示原生屏幕，不猜测任务已完成。

ESP 的“回复”保留回合结果，“终端”同步实时屏幕，原生按键自动切到终端页。默认跟随最新输出，点击“上一页”后保留当前位置，点击“跟随最新”恢复跟随。网络中断时不重复弹窗，自动重连间隔由 1 秒逐步增加到最多 15 秒；配对失效只提示一次并暂停轮询，重新配对后恢复。有待核对回执时只允许重新配对原电脑，原回执不会丢弃。重连只读取状态，不自动重发任务或输入。

设备端只允许私网 IPv4、单个在途 HTTP 请求，响应上限 16 KiB，文字摘要 4 KiB。电脑最多保留 32 个任务、每任务 8 MiB 日志、最多三个项目同时运行，同一项目串行执行；任务默认最长 30 分钟。更完整的输出位于 `.state/<任务编号>.jsonl`。断线不重发任务；提交回执丢失时用“核对操作”按原编号核对。服务重启将正在执行的任务标记为中断，不自动恢复或重发。

`.state/` 含配对凭据、项目路径和任务日志，已被 Git 忽略。桥接 HTTP 仅用于可信局域网，不应映射到公网。自定义 CLI 配置只从电脑本地读取，ESP 不能远程注册可执行程序。

## 结构与安全边界

- `bridge.py`：会话、项目、单次权限确认与输入回执。
- `session_runtime.py` / `process_tree.py`：进程启动、先归属再运行、终止和输出上限。关闭原生终端按“已停止”处理，保留最后的屏幕文字。
- `protocol.py`：协议版本 2、字段校验、控制字符限制、状态转换及尽力隐藏凭据。
- `http_api.py`：HTTP 来源、认证、解析和资源上限。最多 16 个请求线程；请求头总长 16 KiB、单行 8 KiB，请求体 16 KiB，读取超时 5 秒。
- `state_store.py`：私有临时文件、原子替换、落盘和进程实例锁。同一状态目录只能启动一个正式桥接服务。
- `terminal_worker.py` / `native_console.py`：可见窗口和原生控制台；所有模式均在主服务取得进程树归属后才能创建 CLI 子进程。
- `quickapp/claude_control/client.js`：ESP 与电脑网页共用的请求状态机。`ui.js` 只负责 ESP 视图和操作；`app.js` 是生成的固件脚本。

协议 2 的 `submit` 和 `input` 都必须带稳定的 `request_id`。服务保存持久回执；重试相同编号不会再次执行，即使服务重启或旧任务已从列表归档。原生输入有独立送达确认，输入状态为 `queued / delivered / uncertain / failed`；送达只代表进入终端，不代表模型完成任务。断线或确认超时应检查终端再继续，不会自动重发。输入回执文件为 `.state/receipts/input-*`，任务回执同目录长期保留，以免旧编号被再次执行。

权限确认与具体任务绑定，不能重复批准。参数超过可完整展示的上限时，ESP 只能拒绝，请拆分操作后重试。终端文本禁止夹带 ESC、Ctrl-C 等控制字符；需要原生按键时使用协议中明确允许的按键，等待权限确认时不接受输入。自定义 CLI 只能由电脑本地配置，不能覆盖 `claude` / `codex` 内置身份，不能通过远程 API 注册命令，也不经过 shell 拼接。

设备上的 CLI 接口只授予 `builtin:/espclaw/cli.js` 内置来源；同名第三方 QPK 无法取得该身份。存储标识保留 `ai.claude_control`，兼容现有配对信息。

这仍是**可信局域网 HTTP**：没有 TLS，不能防御同网段窃听或已失陷设备。不要将端口映射到公网；不可信网络应使用隔离网络或 VPN。配对令牌拥有项目操作权限，CLI 使用电脑当前用户权限，单次确认不是操作系统沙箱。凭据隐藏仅按已知令牌和常见格式进行，不能保证识别任意秘密；`.state/` 和日志应只允许电脑当前用户访问。令牌泄露时先停止服务，备份并移走 `.state/auth.json`，重启后重新配对所有设备。此操作不会自动重放任何任务。

## 开发验证

在 `tools/claude_bridge/` 运行 `python -m unittest discover -p 'test_*.py' -v`，并从项目根运行 `node tools/claude_bridge/test_client.js`。测试使用隔离状态与本地子进程，不调用模型网关或向 ESP 提交演示任务。Windows 原生终端测试会短暂打开本地测试窗口。

修改 `quickapp/claude_control/client.js` 或 `ui.js` 后，运行 `python tools/generate_cli_resource.py`，同步生成 `app.js` 和 C 内嵌资源。固件使用现有板级配置构建；保留 `GLASS_LOCAL_SPEECH` 和 `QPK_DL_SD_ONLY` 等运行固件所需的可选编译开关。主机 C 测试为 `tools/test_claude_http.py`，原生 LVGL 布局验证使用 `tests/render_claude_control.c`。
