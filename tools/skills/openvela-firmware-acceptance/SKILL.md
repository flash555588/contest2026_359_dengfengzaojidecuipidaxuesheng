# openvela 固件候选与分层验收

定位含 `tools/build_bilibili_v3.py` 的项目根并读 `AGENTS.md`。先核对用户任务范围：分析、构建、烧录或实测分别执行到已授权阶段。历史会话授权不自动成为当前设备操作授权，已有本轮授权则继续完成。

## 固化确切候选

记录 Git revision、相关未提交源码摘要、生成资源和构建选项。overlay 才是可维护源，准备树是构建输入；不能只改临时树后交付未同步的仓库源码。提示词/schema/UI 改动同步相应生成产物。

选择显式、兼容的 prepared baseline，在独立 workspace 构建，核对依赖、TLS/模型/素材版本及参数。沿用准备基线的数据布局；不从旧脚本复制烧录地址、12m/14m 分区或 PSRAM 预留。构建入口和参数见 [references/project.md](references/project.md)。

链接/内存配置变化后检查最终 ELF 和镜像，防止旧对象携带旧预留。保留启动 BSS、链接符号和应用/数据边界检查。对象 `.bss` 统计不等于最终固件余量，编译一个对象也不等于整机链接成功。

## 让每个结论对应证据

分别记录：宿主回归、P4 对象交叉编译、最终链接/镜像、写后校验、复位/冷启动、真实功能与用户观察。报告候选摘要、测试场景/时长、失败和未覆盖项。

- 模拟器/替身不能证明真实模型、摄像头、DMA、扬声器回声或家居控制通过。
- 串口处理了“返回桌面”命令不能证明物理屏幕恢复；截图也不能证明无瞬时闪屏。
- 多次软件复位不能称为断电冷启动，短期运行不能称为长期稳定。
- 实验失败保留症状和证据，不用后续局部通过覆盖。发现黑屏/卡死时停止自动重复触发，按本轮授权恢复可用候选再定位。

## 保持可恢复

烧录前确认实际设备、当前串口/USB 角色、镜像范围与适用的备份/回退镜像。烧录后核对镜像和启动状态。恢复任务结束后的服务、页面及端口使用状态，明确板上当前保留哪个版本。

只交付本次范围内的文件和证据，保持用户已有改动；源码、材料、SD 成品包与历史开发记录按用户选择提交。没有明确当前授权不自行提交或推送。
