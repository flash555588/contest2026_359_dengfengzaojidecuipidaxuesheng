# ESPClaw 语音链路与所有权

定位项目根并读 `AGENTS.md`。先画出本次链路：唤醒 → 录音 → 结束语句 → ASR → AI/工具 → TTS → 待命，分别标注麦克风所有者、request/session ID、任务组和取消确认。源码与测试选择见 [references/project.md](references/project.md)。

## 不让旧结果进入新请求

- 全局浮球、大球和语音面板使用明确请求身份。新请求接管旧录音后，晚到转写/模型结果只能归原请求，不能发送到当前 AI 或重开旧页面。
- 当前大球页面由大球承接本页唤醒，按现有产品规则处理全局浮球；共用服务不应制造两套同时响应的录音 UI。
- 采音和网络发送分离，避免阻塞网络拖住麦克风回收。取消后先等后台工作线程和回调实际退场，再清理上下文；超时不释放 DMA 或服务仍持有的对象。
- 常驻服务从常驻任务组创建。短生命周期 NSH 命令不应创建随后脱离其任务组资源的常驻音频线程。

## 播报打断必须证明并行采音

检查 TTS 播放期间实际有 RX 数据和检测器输入；仅触摸停止、注入 wake 回调或播放结束后再监听，不证明语音打断。

ES8311 观察者共享当前 16 kHz 播放时钟，不再次 RESERVE/CONFIGURE 或重置声卡。退出时先撤销 RX、同步归还回调，再 join 和释放缓冲，最后关闭播放所有者。核对当前 P4 I2S timeout 是否实现，不能以应用等待超时推断 DMA 已停止。

## 把链路验收与识别效果分开

先用替身覆盖请求抢占、取消、旧回执、RX 停止和资源复用，再做真人的完整唤醒至播报与播报中打断。扬声器回声、底噪、远场和长时间待机分别记录。

合成语音检出率不是真人准确率；MFCC/DTW 模板拟合不称为重新训练 WakeNet。按声线/说话人隔离再增广，参与调参的集合标为开发集。调整阈值时同时报告漏检、误触发和旧场景退化，不只报告改善的一项。
