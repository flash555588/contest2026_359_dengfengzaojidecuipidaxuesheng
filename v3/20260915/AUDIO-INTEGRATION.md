# 蓝牙耳机／音箱放音接入要求

当前板使用 ESP32-P4 主控和 ESP32-C6 无线协处理器。C6 提供 BLE，不具备经典蓝牙 BR/EDR。普通耳机／音箱的立体声放音通常使用经典蓝牙 A2DP，桌面需要担当 **A2DP Source（音频发射端）**。仅增加配对按钮、切换 NimBLE/Bluedroid 或启用 SBC 格式选项，不能给 C6 增加经典蓝牙无线能力。

本次固件已实现 BLE 广播／扫描响应中的名称显示，尚未实现经典蓝牙配对、耳机音频路由或放音。BLE 扫描中出现某副耳机的名称，也不代表可以通过它的 BLE 广播通道播放音频。LE Audio 另需匹配的控制器、等时传输、音频协议和编解码支持，当前硬件与固件没有可直接启用的完整实现。

## 可实施的硬件路径

| 路径 | 所需硬件及接口 | 能实现的桌面体验 |
| --- | --- | --- |
| 外接经典蓝牙音频发射模块 | 明确支持 **A2DP Source**；有 UART 控制协议，能返回扫描结果、设备名和配对／连接状态；音频输入采用 I2S 或模块支持的模拟输入 | 桌面列出设备名，选择配对、连接、断开和放音；具体控制命令按模块手册实现 |
| 外接原版 ESP32 开发板，例如 ESP32-WROOM-32 | 原版 ESP32 的经典蓝牙能力；独立固件实现 A2DP Source；UART 传送控制事件，I2S 接收来自 P4 的 PCM | 可自行实现发现、名称、绑定保存、重连、音频和 AVRCP；需要编写协处理器固件并验证音频时序 |

“蓝牙音频接收板”通常是 A2DP Sink，不能代替这里需要的发射端。原版 ESP32 路径也不能用只有 BLE 的 ESP32-C3/C6/S3 直接替换。

## 接入时需要实现的内容

1. 经典蓝牙发现与名称查询：读取 EIR 名称，缺少名称时执行远端名称查询；地址作为备用标识。
2. 配对与绑定：处理认证结果、必要的 PIN／确认交互、保存绑定、删除设备和重连。蓝牙 UI 依据真实事件显示“已配对”和“已连接”。
3. 音频：将播放器 PCM 输出路由到发射模块，按协商的采样率和声道进行转换、缓冲；实现播放、暂停、停止和音量同步。当前本机 ES8311/I2S 配置为 16 kHz、16 位，不能直接假定等于耳机的 A2DP 协商格式。
4. 验证：指定耳机／音箱的配对、实际声音、连续播放、断开重连，以及 Wi-Fi 共存。需要模块型号、接线资料和测试耳机／音箱型号，才能确定引脚与协议并完成实板验证。

P4 已有 I2S0 引脚用于板载音频，本说明不预先指定外接引脚或直接并联音频总线；模块和接线确认后再确定可用接口。

参考：[乐鑫 A2DP Source 接口与官方示例](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/bluetooth/esp_a2dp.html)。下载快照位于 `evidence/audio-reference/`；当前 C6 的 `BLE-only (no BR/EDR)` 能力回报保存在实板串口验证记录中。
