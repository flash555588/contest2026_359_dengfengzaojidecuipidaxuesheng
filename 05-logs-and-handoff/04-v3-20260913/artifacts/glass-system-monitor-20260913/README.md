# ESP32-P4X-Function-EV-Board · openvela 桌面性能候选

后续已生成包含 QPK 回收修复与后台设置保存的
[生命周期候选](../glass-lifecycle-20260913/README.md)。本目录保留性能页阶段产物。

本候选接续后台文件服务版本，新增“设置 → 性能”页面，并减少过期数据的
无效刷新。已完成 v3 离线编译、链接和核验，尚未进行实板验收。

## 新增能力

性能页读取真实 openvela API：CPU 按所有 idle PID 的活动量和同一个全局
总量计算，范围 0–100%；堆数据来自 mallinfo，包括总堆、可用量、最大连续
空闲块和历史使用峰值。CPU 统计未启用、计数尚未有效、采样跨越不同周期或
堆数据异常时显示缺失状态，不把不可用数据写成 0。

采样线程仅在页面打开时存在，每秒采样一次，使用单调时钟条件等待；
关闭页面唤醒线程并丢弃界面引用，不等待正在进行的堆查询。数据采集与
LVGL 对象分离，旧采样尚未结束时重开页面会等待收尾。目标线程栈为
8192 字节，循环内不分配采样缓冲区。页面文字只在显示值变化时更新。

已过期的 Home Assistant 同步提示改成分钟、小时、天粒度；有效数据仍按秒
展示，60 秒过期规则保持不变。固定时钟宿主测试中，过期后连续 59 秒没有
重绘，分钟/小时边界会正确更新。此前的后台文件操作和相同内容刷新优化保留。

## 验证

默认、v3 Wi-Fi、v1 Wi-Fi 三种配置各通过 6 项测试；构建脚本的 18 项测试
也通过。测试覆盖双核分母、零计数、计数周期不一致、统计关闭、堆边界、
采样频率、慢采样时关闭/重开、100 次监控器启停和 100 次性能页开关。
文件窗口与性能窗口循环后，定时器保持 4 个、文件句柄保持 7 个；
相同性能数据重复刷新 20 次没有产生重绘。

文件服务及监控器通过 AddressSanitizer、LeakSanitizer 和
UndefinedBehaviorSanitizer；六个生产单元完成 RISC-V 编译，完整固件
链接通过。核验脚本确认 17 个生产输入与构建树、固件元数据一致，并检查
文件服务、监控器、CPU/procfs、相机、C6 和 ESP-Claw 的最终符号。

## 剩余工作

没有构建新的 v1 镜像，也没有刷机。v3 仍沿用 301–399 修订范围及原有
Simple Boot 无附加摘要格式，冷启动、复位、Wi-Fi、相机和长稳仍需实板。
本机测试不能证明实际 CPU 降幅或整板没有泄漏。

相机停止当前仍为 STREAMOFF → pthread_join → 解除映射/释放缓冲区；
停止失败和等待时间需要结合设备验证，不能提前释放 DMA 仍可能使用的内存。
QPK 回调生命周期本轮未修改。壁纸的 509184 字节是桌面生命周期缓存，
不应仅因关闭普通页面后仍存在就判为泄漏。

下一步使用本候选记录空闲、文件复制、取消恢复和相机/应用启停时的 ps、
free、/proc/cpuload，保留固件哈希，并完成 100 次应用启停与 30 分钟长稳。
性能页会增加自身的少量栈和页面占用，测量其他应用恢复基线时需关闭它。
