# 超时机制与实板验证

这次处理运行时计时与任务边界，不按应用名称扩大执行上限。已删除家居和 Grok Ball 的 1500ms 特例。

| 范围 | 机制 | 检查结果与处理 |
| --- | --- | --- |
| JS 编译 | 独立、有限的 10 秒编译阶段，内存和栈限制继续生效 | 原先编译和初始化共同占用 250ms，正常内置页面也会被中断。使用 `JS_EVAL_FLAG_COMPILE_ONLY` 与 `JS_EvalFunction` 分离，与草稿编译的阶段语义一致。 |
| 初始化 | 所有应用统一 250ms 执行预算 | 家居控件创建按分组与卡片分次进行；小球首帧交给后续绘制任务。 |
| 按钮与触摸 | 80ms | 保留交互限制；回调和其 Promise 任务共享同一期限，不再重新发放一份预算。 |
| 定时器及 yield 恢复 | 250ms | 恢复函数与后续任务均纳入期限。异步错误传回调用方，失败的定时器会停止。 |
| 嵌套调用 | 子调用不能超过父期限 | 保存与恢复父期限；防止内层调用结束时清空外层保护。 |
| Promise 队列 | 在实际待执行任务之间检查期限 | 阻止短任务持续追加形成的无限链。队列为空则正常完成，避免已完成操作被追溯判为超时。 |
| HA 请求、重试与状态确认 | 单调时钟；请求 12s、确认 8s、刷新 10s | 使用 `ui.nowMs()`；同步记录时间仍为真实时间。系统校时不再让请求立刻过期或让刷新长期停住。原 HA 原生传输自身的 5s 请求边界保留。 |
| HTTPS 等待 | 调用等待期限与请求期限取较早者 | `poll` 遇到 EINTR 后使用剩余时间，避免每次信号重新等待完整时长；取消仍优先返回。 |
| 小球绘制 | 每次遍历约 15ms；首帧及后续帧可分次完成 | 缓存路径和变换结果；保持遍历层级和绘制顺序，未完成的帧期间不推进动画状态。 |
| 音频和硬件任务 | 工作线程自己的 I/O、取消、停止边界 | 与 JS 执行预算分开；实板诊断验证录音、WAV 元数据、播放、停止、取消及临时文件清理。 |
| 串口 UI 检查 | 独立诊断请求与布局报告 | 只作诊断。串口报告可能丢字节，测试会重试；未恢复的报告只保留完整接收的对象，不补造数据。 |

相关修复之外，固件补齐了 `CONFIG_SYSTEM_HASS=y`，保持精确源文件授权和原 `system.homeAssistantService` 接口。桌面启动挂载现有 `/data`，不会自动格式化。实板上的数据区曾完整备份并核对全为 `0xff`，随后才初始化空 SmartFS。

回归使用实际生产函数和真实 QuickJS，并启用 ASan/UBSan：普通死循环、无限 Promise 链、嵌套期限、回调与任务共享预算、空任务队列、异步错误传播；另有 HA 校时模拟、HTTPS 信号重试及取消、32 种小球状态与慢设备绘制分次完成的检查。

实板记录在工作区 `output/refined-ui/board-test/`。入口检查与功能检查分开记录。HA 与 AI 服务尚未配置，入口通过不等于远端业务请求通过；ESP-DL 推理需要受支持的 USB MJPEG 相机，缺少设备时按阻塞记录，不能以默认 `error=0` 当作推理成功。
