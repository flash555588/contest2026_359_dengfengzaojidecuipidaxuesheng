# 声动音乐与中文输入

文字 PV 的 SD 配色入口、27 套风格与离线素材包见 [JIZURA SD 素材说明](../jizura/SD-ASSETS.md)。原生页新增 SD 风格切换，构图仍使用已有八种布局；完整版效果的浏览器预览与原生移植边界分别记录。

原生 LVGL 音乐应用，面向 1024×600 的 ESP32-P4 Function EV Board。布局采用侧边导航、歌曲列表、右侧唱片和底部播放控制，适配浅色与深色主题。

## 使用

ESPClaw 助手模式可直接调用内置 board MCP 的音乐工具，搜歌、播放、暂停／继续、停止、调音量和收藏列表切歌均复用系统音乐服务。结果在对话内以音乐小卡片显示，不打开音乐页面；播放由后台服务托管。播放等请求返回受理状态，`music_status` 用于查询后续播放状态。完整工具边界和验证入口见 [AGENT-CAPABILITIES.md](AGENT-CAPABILITIES.md#内置音乐工具board--music_)。

助手搜歌后用原搜索词和 `result_id` 播放已核对的结果，60 秒内可用一次，省去第二次检索并绑定演唱版本；
过期、被替换或已使用时明确拒绝。指定歌手不匹配时不播放替代版本。音乐与米家控制的完整调用参考见
[流程实例](AGENT-CAPABILITIES.md#音乐与米家控制实例)。

- 点击桌面音乐卡片进入「声动」，点搜索栏输入歌名或歌手。
- 中文模式使用 Android 开源项目的 Google 拼音引擎（libgooglepinyin 0.1.2，Apache-2.0），附带约 6.5 万词、1,068,442 字节的离线词频词库。输入连续拼音即可选字、词或整句，支持分段选词；例如 `nihao` 首选「你好」，`woxihuanyinyue` 首选「我喜欢音乐」。左右箭头翻页，空格选当前页首项。
- 点击「中 / EN」切换中英文；`1#` 输入数字与符号。按键在抬手时生效，长按不连发。输入中的第一次确认负责选字，再次确认提交。
- 点歌曲开始播放；底部可暂停、恢复、调节音量和收藏。上一首、下一首在收藏列表中循环。退出应用后继续播放。
- 收藏最多 20 首，保存到 `/data/qpk/music`。保存歌曲信息与搜索词，每次播放重新获取地址，避免保存已过期的链接。

中文键盘也已接入 Wi-Fi 名称、文件新建/重命名及快应用输入框。密码框保留英文输入。

引擎用户词典位于 `/data/qpk/pinyin/user.dat`，关闭输入框时刷新缓存。系统词库直接从固件内存读取，不占用用户数据分区。长候选自动减少每页候选数量以获得更多显示空间。

## 接口与实现范围

参考 MicroReactor 的音乐接口协议，使用 `jkapi.com` 的 QQ 音乐检索。该接口每次返回一首匹配歌曲，曲库可用性依赖接口和资源提供方。当前支持 MP3 流播放，不提供歌词、完整专辑列表、离线下载或拖动定位。右侧为应用绘制的唱片图案；计时来自实际音频缓冲区完成数量。

网络使用验证证书的 TLS，256 KiB 环形缓冲与独立下载线程，minimp3 解码后下混为单声道，通过共享 ES8311 设备及 GPIO53 功放输出。搜索、播放和收藏落盘均在工作线程执行。停止和切歌通过代次编号取消旧请求。

私有 `music_credentials.h` 由 `diagnostics/prepare_music.py` 从参考工程中提取音乐接口密钥生成，已加入忽略规则；日志不记录密钥或带签名的播放地址。`music_vendor` 保存解码器、拼音引擎及许可证。Google 拼音源码来源、源码包/词库 SHA-256 与移植说明见 `music_vendor/googlepinyin/manifest.json`。移植固定了词库的 32 位整数格式、修复两处释放遗漏，并匹配 NuttX 的整数类型；候选搜索及词频算法沿用开源引擎。

- `diagnostics/test_ime.py`：真实 LVGL 指针输入，覆盖点击、两秒长按、两次独立点击、词频排序、整句输入、分段选词、英文/数字切换和控件销毁，使用 ASan/UBSan。

## 全屏歌词播放器

音乐侧栏的「全屏歌词」、封面及歌词预览可进入 1024×600 全屏页。当前歌词按实际播放时间高亮并自动跟随；手动上下滚动可浏览整首歌词，点「恢复跟随」回到当前行。固定复用 9 个行控件，通过带锁的窗口副本读取至多 192 行，切歌立即清理旧歌词；前奏、加载、缺失及停止状态不伪造歌词。

播放中换行采用平滑滚动和 320ms 的当前行渐亮；只对新进入的当前行执行一次，不循环闪烁。暂停、手动浏览及「减少动态效果」关闭渐亮，复用行控件或切歌时取消旧动画。

全屏页提供暂停／继续、收藏列表上一首／下一首、收藏及音量。进度条仅显示实际播放进度，不提供尚未实现的拖动定位。返回音乐、返回桌面或关闭歌词页不停止后台播放器；锁屏及父页面销毁会清理全屏控件并恢复状态栏。MCP 音乐调用仍只在对话中显示结果，不自动打开本页。真实在线播放需要在扫码配置的「音乐服务」中设置 API Key。

`render_music_full.c` 使用真实 LVGL 验证明暗主题、原生触摸滚动、手动浏览保持、恢复跟随、播放控制、切歌、缺词和 60 次复开；音乐服务测试另覆盖完整 192 行窗口边界、只读副本与真实 MP3 工作线程。截图中的原创歌词是测试夹具，不代表已完成真实曲目播放验收。

### 三套实时文字效果

全屏页点「文字 PV」进入，右上角依次切换「聚焦」「强调」「逐字」三套效果。聚焦使用居中大字与短暂渐亮，强调使用前句小字、末句强调色大字，逐字使用固定排版与完整 UTF-8 前缀显现。底部细线使用整行歌词的实际时长；逐字效果不是逐词卡拉 OK 对齐，也不做语义或节拍识别。

新歌获得 LRC 后直接在板端排版，不需要电脑为歌曲生成帧素材。复用现有 20／28／48／72 号字体和三个文字标签，无动画专用图片缓冲、解码线程及歌曲帧库读取；SD 原有音乐和歌词读取保持不变。大字不持续移动，细线最多 32 档，逐字更新按 80ms 时间格限制，50ms 定时器只在页面可见时工作。定时器频率不是实测帧率。

动画以解码音频的实际播放位置为准，暂停不前进，回跳重建正确前缀，减少动态效果显示完整静态歌词；切歌、缺词和错误清理旧画面。返回页面继续后台播放，MCP 控制不会自动打开本页。

`render_music_full.c` 使用真实 LVGL 与 ASan／UBSan 检查两种主题、三套效果、任意中英文歌词及长句、UTF-8 显现、暂停、回跳、减少动态效果和 60 次开关。实板结果与主机结果分开记录于工作区 `output/jizura-device-20261018/`，在线首播时间仍需真实网络测量。

完整 JIZURA 浏览器复刻见 [完整版](../jizura/README.md)。固件已移除旧原生编排与 SD 预渲染播放分支，仅保留三套实时效果。离线帧格式校验位于 `app/jizura/device-codec`，不参与固件编译；完整 Canvas2D、编辑器与 MP4 导出属于浏览器版本。

### 封面与歌词 API（lrc.cx）

默认使用 `https://api.lrc.cx/jsonapi` 获取候选歌词，按歌名和歌手匹配，保留 LRC 原始时间轴；优先使用匹配结果的 320px `cover_format`，没有封面时使用独立的 `https://api.lrc.cx/cover`。歌词缺失或接口失败时仍可请求封面，音频不等待这些请求。扫码配置中的音乐 API Key 只用于音乐检索，lrc.cx 不需要额外密钥。

成功的歌词响应与已成功解码的 JPEG 封面缓存在 `/sdcard/music/cache`。歌词和封面各使用 32 个固定替换槽；缓存验证完整请求身份、长度及校验值，哈希槽冲突只会替换，不会返回另一首歌的数据。缓存写入失败不影响播放；损坏缓存回退网络；没有歌词的响应不持久缓存。本地手动 LRC 优先，纯 SD 音频仍不等待网络。

封面下载上限为 2 MiB，源图单边不超过 4096px、总像素不超过 1200 万；显示时优先缩至 368px 内，最大 1/8 JPEG 缩放后允许至 512px。当前使用 baseline JPEG 解码器，PNG／WebP／progressive JPEG 等不支持的返回保留占位图。官方接口可能返回其他图片格式，不能保证全部歌曲都有可用封面。接口说明见 [官方歌词文档](https://docs.lrc.cx/docs/legacy/lyrics/) 与 [官方封面文档](https://docs.lrc.cx/docs/legacy/cover/)。

2026-10-18 主机联网核验：lrc.cx 查询的真实响应通过同源解析器，精确匹配候选获得 44 行时间轴；独立封面返回 858,760 B JPEG，同源解码器成功将 3000×3000 缩为 375×375。以上是主机联网和同源代码测试，不替代 ESP 在线整条链路验收。封面共享于音乐页、全屏歌词和锁屏，MCP 后台播放仍不自动打开应用。

该更新已烧录到 P4 并通过启动检查，应用 SHA-256 为 `c2dc31f2449357f23f066dc9c6cbda59a62b5e14e2ff0892b3be50ead9481a0d`。实板整曲联调在音乐搜索阶段返回 `-EINVAL`，尚未进入播放与 lrc.cx 请求阶段；按当前实现指向未配置音乐搜索 API Key，因此不宣称实板封面与歌词整链路通过。配置入口为扫码配置的「音乐服务」。三套效果实板压力测试已按用户要求停止，完成并记录到第 50 次检查点，未将它标记为 60 次通过。

### SD 多语言字库、简体显示与双语歌词（2026-10-18）

原内置 Alibaba 字库有 8,283 个 Unicode 映射，《海阔天空》一次真实 LRC 响应中有 27 个繁体／异体字缺失。现在保留内置字体作为首选，将 Noto Sans SC／JP／KR 和 Noto Sans 的固定 400 字重合并为 `/sdcard/fonts/VelaGlobal-Regular.ttf`；各源文件与 OFL 许可证按 `assets/music-fonts.lock.json` 的固定提交和 SHA-256 验证。

合并字体为 13,157,208 B，覆盖 45,695 个 Unicode 字符，包括 11,172 个预组合韩文音节、常用日文假名／汉字、扩展拉丁、希腊与西里尔字母。英文、法语、西班牙语、葡萄牙语、德语、土耳其语、越南语、俄语、乌克兰语等可使用对应字形。此列表表示字符覆盖，不代表任意 Unicode 或复杂文字排版已支持；当前没有启用阿拉伯文双向／连写、印度文字排版或组合附标定位引擎，韩文示例使用 NFC 预组合音节。

字体文件不整体装入内存。私有 TinyTTF 文件后端复用当前固定版本 LVGL 源码，以独立符号启用文件读取，不改全局 Kconfig 或内置内存字体。五种字号共用一个只读 SD 文件句柄和 32×4 KiB 的 LRU 文件页缓存，使 cmap／hmtx／loca 和字形轮廓在字号间复用；字形缓存上限依次为 96／128／128／32／24。后台先验证完整文件长度和 FNV 校验，再由 UI 线程创建、连接回退字体；缺失、截断或校验失败时保留内置字体及图标。FNV 是损坏检查，不是来源签名；来源校验使用构建／部署清单中的 SHA-256。文件须在开机前放好，替换后重启。

歌词独立使用真正的 72px 字体，避免首页历史上名为 `font72` 的 128px 字体导致测量／裁切不一致。锁屏的播放快照改为随锁屏创建和释放的 PSRAM 缓存，避免双语字段挤占内部静态 RAM。

中文歌词在音乐工作线程中使用 OpenCC t2s 字符及短语词典转为简体。词典固定在 OpenCC `ver.1.1.9`，许可、来源和校验在 `assets/opencc/`，生成器为 `tools/generate_music_hans.py`。包含假名／韩文的原文按歌曲保留汉字字形；`[language:ja]`、`[language:ko]` 也可明确保护全汉字原文。中文译文单独转换，不改歌曲查找、缓存身份和音频地址。

双语数据来自同时间戳的两行 LRC、接口随附的 `translated_lyrics`／`translation`／`tlyric.lyric` 字段，或 SD 独立译文文件。译文只绑定相同毫秒时间戳，未匹配的行保持原文；不伪造翻译或另起收费机翻调用。当前 lrc.cx 的基础接口不保证每首歌曲包含译文。

手动译文放在 `/sdcard/music/lyrics/<歌名> - <歌手>.zh.lrc`，原文使用同名 `.lrc`。长文件名可用既有 `music_track_key()` 的八位十六进制身份，分别保存为 `<key>.lrc` 和 `<key>.zh.lrc`。原文与译文都使用 UTF-8 LRC；译文填补未有译文的匹配行，不改变原文时间轴。上限为 192 个独立时间点，每行原文和译文分别为 191 B 的完整 UTF-8 前缀，窗口仍只复制 9 行。
